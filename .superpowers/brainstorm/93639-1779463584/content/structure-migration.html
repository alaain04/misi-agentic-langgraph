src/ ├── api/ # unchanged ├── db/ # unchanged ├── domain/ │ └── ports/ # add EvidenceStorePort ├── models/ # add Evidence, Hypothesis, RiskFinding, InvestigationPlan ├── services/ # unchanged (job_dao, job_runner) └── main_graph/ ├── graph.py # rewired — 6 backbone nodes ├── state.py # replaced with new MainState ├── constants.py # updated node names ├── config.py # add skill_registry to services │ ├── skills/ # NEW — replaces ingestion_subgraphs/ │ ├── base.py # InvestigationSkill ABC, SkillContext, Evidence │ ├── registry.py # SKILL_REGISTRY dict + SKILL_DESCRIPTIONS │ ├── vulnerability.py # wraps vulnerabilities subgraph logic │ ├── maintainer_trust.py # wraps repo subgraph (commits, issues) │ ├── supply_chain.py # wraps registry subgraph │ ├── license.py # wraps license_compliance subgraph │ ├── reachability.py # wraps impact subgraph │ ├── blast_radius.py # new │ ├── release_anomaly.py # wraps repo subgraph (releases) │ └── ecosystem.py # wraps registry subgraph │ ├── nodes/ │ ├── investigation_planner.py # replaces orchestrator + planner │ ├── skill_dispatcher.py # replaces execution_planner + task_dispatcher │ ├── skill_executor.py # replaces execute_plan │ ├── evidence_collector.py # replaces stage_advance │ ├── evidence_correlator.py # replaces cross_analyzer │ ├── finding_reviewer.py # replaces report_reviewer │ └── report_builder.py # new — deterministic assembly │ └── subgraphs/ └── discovery/ # unchanged

Migration strategy — what to keep, wrap, and rewrite

Current component Migration action Risk
discovery subgraph Keep as-is. Zero changes. none
vulnerabilities/service.py (Trivy logic) Move into VulnerabilitySkill.execute(). Same logic, new wrapper. low
license_compliance/service.py Move into LicenseSkill.execute(). low
impact subgraph (reachability) Move into ReachabilitySkill.execute(). low
repo subgraph (commits/issues/releases) Split into MaintainerTrustSkill + ReleaseAnomalySkill. Same MCP calls. medium — split logic carefully
registry subgraph Split into SupplyChainSkill + EcosystemSkill. medium
orchestrator + planner Rewrite as investigation_planner. New prompt, new output schema. medium — prompt engineering
execution_planner + task_dispatcher Rewrite as skill_dispatcher. Same Send() pattern, new input shape. low — mostly mechanical
execute_plan Rewrite as skill_executor. Calls skill.execute() instead of subgraph.invoke(). low
stage_advance Rewrite as evidence_collector. Same fan-in, accumulates Evidence[]. low
cross_analyzer (dict merge) Full rewrite as evidence_correlator. Correlation + contradiction + confidence. high — most complex new code
report_reviewer Rewrite as finding_reviewer with structured criteria + HITL gate 2. medium
risk_score + recommendation nodes Absorbed into evidence_correlator. No separate nodes needed. none — delete
MainState Replace. Keep discovery fields. Drop execution tracking fields. Add evidence[]. medium — cascades to all nodes
API layer, job_dao, job_runner Keep as-is. External contract unchanged. none

Safe migration order: Start with the data models (Evidence, Hypothesis, InvestigationPlan, RiskFinding) and the skill base class — these have no LangGraph dependencies. Then wire skills one by one, replacing ingestion subgraphs from simplest (license) to most complex (repo split). Replace graph nodes last, once all skills are tested in isolation. The API contract never changes.
