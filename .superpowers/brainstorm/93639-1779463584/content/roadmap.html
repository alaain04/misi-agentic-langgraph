Section 6 — Implementation Roadmap

Four phases. Each phase is independently shippable and leaves the system runnable.

PHASE 1 Foundation

Data models + skill base. No graph changes yet. System still runs on old pipeline.

  • Define Evidence, Hypothesis, InvestigationPlan, RiskFinding models
  • Define InvestigationSkill ABC + SkillContext
  • Implement SKILL_REGISTRY with all 8 skills (stubs ok)
  • Update MainState — add new fields alongside old ones
  • Unit tests for Evidence model, confidence arithmetic

Deliverable: all data models typed, skill registry wired, state backward-compatible

PHASE 2 Skills

Migrate existing analyzer logic into skills. Test each skill in isolation.

  • Implement LicenseSkill (simplest — pure SBOM logic)
  • Implement VulnerabilitySkill (wrap existing Trivy service)
  • Implement ReachabilitySkill (wrap impact subgraph)
  • Implement MaintainerTrustSkill + ReleaseAnomalySkill (split repo subgraph)
  • Implement SupplyChainSkill + EcosystemSkill (split registry subgraph)
  • Implement BlastRadiusSkill (new — dep graph traversal)
  • Integration test: each skill returns valid Evidence[] for a real repo

Deliverable: all 8 skills implemented and tested independently

PHASE 3 Graph Rewire

Replace graph nodes. This is when the new pipeline goes live end-to-end.

  • Implement investigation_planner node (new LLM prompt + output schema)
  • Implement skill_dispatcher (Send() per skill_plan entry)
  • Implement skill_executor (calls skill.execute(), writes Evidence[])
  • Implement evidence_collector (fan-in, replaces stage_advance)
  • Implement evidence_correlator (contradiction detection + confidence + LLM synthesis)
  • Implement finding_reviewer (structured criteria + HITL gate 2)
  • Implement report_builder (deterministic assembly)
  • Rewire graph.py — remove old nodes, add new backbone
  • End-to-end integration test on a real CodeTech project

Deliverable: full new pipeline running end-to-end, old nodes deleted

PHASE 4 Epistemic Hardening

Strengthen evidence quality, contradiction resolution, and thesis validation.

  • Tune confidence weights per evidence kind (empirical calibration)
  • Add missing-evidence tracking to RiskFinding.missing_evidence[]
  • Implement corroboration bonus in confidence model
  • Add contradiction resolution strategies (not just detection)
  • Enrich HITL gate 2 — show evidence provenance to user, not just findings
  • Evaluate against CodeTech projects — validate thesis hypothesis
  • Frontend: update DAG visualization to show skills + evidence, not subgraphs

Deliverable: system validated on real projects, thesis evaluation complete

What is deterministic vs LLM-driven

Component Mode Why
Evidence grouping Deterministic Pure function, always reproducible
Contradiction detection Rule-based Auditable, no hallucination risk
Confidence arithmetic Deterministic Scores must be traceable to evidence weights
Skill dispatcher (Send() fan-out) Deterministic Mechanical iteration over skill_plan
can_run() guard Deterministic Prevents silent partial execution
Hypothesis generation LLM Requires understanding of concern + context
Skill selection per hypothesis LLM Trigger matching requires semantic reasoning
Finding synthesis (summary, recommendation) LLM Narrative generation from structured evidence
Review criteria evaluation LLM Semantic judgment of coverage and coherence
Intent classification (approve/change/cancel) LLM Natural language understanding required

Thesis alignment: Phase 3 delivers the core thesis contribution — a system that identifies high-risk dependencies with traceable confidence scores, detects contradicting signals, and presents structured evidence to a human reviewer. Phase 4 validates it empirically against CodeTech's real projects, which is what the thesis evaluation requires.
