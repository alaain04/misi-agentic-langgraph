Section 4 — The Two Cognitive Nodes

investigation_planner and evidence_correlator — where reasoning happens

investigation_planner — replaces orchestrator + planner

Reads the concern + SBOM, generates hypotheses per dependency, assigns skills to each hypothesis. Outputs a structured InvestigationPlan that is presented to the user for approval (HITL gate 1).

# System prompt — what the LLM receives PLANNER_SYSTEM = """ You are a dependency risk investigation planner. Given a project's SBOM and a user concern, you must: 1. Generate risk hypotheses for the most relevant dependencies. Each hypothesis is a falsifiable statement about a specific risk. Example: "lodash@4.17.20 may expose the project to prototype pollution attacks" 2. Assign investigation skills to each hypothesis. Choose skills whose trigger_conditions match the hypothesis risk theme. 3. Explain your rationale — why these hypotheses, why these skills. Available skills: {skill_descriptions} Output JSON: { "hypotheses": [ { "id": "h1", "dep_name": "lodash", "statement": "lodash@4.17.20 may expose prototype pollution attacks", "risk_theme": "vulnerability", "rationale": "lodash has 3 known prototype pollution CVEs", "skills": ["VulnerabilitySkill", "ReachabilitySkill"] } ], "dep_filter": null, "rationale": "Focused on security given concern about CVEs" } """

What's new vs current planner

  • Outputs hypotheses, not subgraph names
  • Each hypothesis has a falsifiable statement
  • Skills are assigned per hypothesis, not globally
  • LLM explains its rationale (auditable)
  • HITL gate shows hypotheses to user — more meaningful than "run vulnerabilities subgraph"

What stays the same

  • Same interrupt() pattern for HITL
  • Same re-plan loop on "change" intent
  • Same intent classifier (approve/change/cancel)
  • Same vector store embedding of conversation

evidence_correlator — replaces cross_analyzer (dict merge → reasoning engine)

Receives all Evidence[] from the shared state. Correlates signals across skills and deps, detects contradictions, scores confidence, produces RiskFinding[] per dependency.

async def evidence_correlator(state: MainState) -> dict: evidence = state["evidence"] # Evidence[] from all skills hypotheses = state["investigation_plan"]["hypotheses"] # Step 1 — deterministic grouping by_dep = _group_by_dep(evidence) # pure function, no LLM by_hypothesis = _group_by_hypothesis(evidence) # Step 2 — contradiction detection (rule-based) contradictions = _detect_contradictions(evidence) # e.g. VulnSkill says "critical CVE" but ReachabilitySkill says "dep not imported" # Step 3 — confidence scoring (rule-based) raw_scores = { dep: _compute_confidence(evs) # weighted avg of evidence.confidence for dep, evs in by_dep.items() } # Step 4 — LLM synthesis per dep (structured output) findings = await _synthesize_findings( by_dep, by_hypothesis, raw_scores, contradictions, state["concern"] ) # LLM reads structured evidence, produces RiskFinding per dep # with risk_score, summary, recommendation, alternatives return { "risk_findings": findings, "contradictions": contradictions, }

Contradiction detection — concrete example

Evidence A (VulnerabilitySkill): lodash has CVE-2021-23337, severity=high, confidence=0.95 Evidence B (ReachabilitySkill): lodash is not imported in any execution path, confidence=0.82 → Contradiction: high-severity vuln in an unreachable dependency → ContradictionReport { evidence_ids: ["ev_A", "ev_B"], description: "CVE-2021-23337 is high severity but lodash is unreachable", resolution: "effective_risk_reduced", adjusted_confidence: 0.35 ← down from 0.95 }

Confidence scoring model

  • Base score = weighted average of evidence.confidence × evidence.reliability
  • Contradiction penalty = −0.2 per unresolved contradiction
  • Missing evidence penalty = −0.1 per required-but-absent evidence kind
  • Corroboration bonus = +0.1 when 2+ independent skills agree
  • Final score clamped to [0, 1] — feeds directly into RiskFinding.confidence

finding_reviewer — structured review, not free-form LLM loop

# Reviewer checks specific quality criteria — not "does this look good?" REVIEW_CRITERIA = [ "Every high-severity finding has ≥2 supporting evidence items", "No finding has risk_score > 7 with confidence < 0.5", "All contradictions are explicitly addressed in the finding summary", "Every high-risk dep has at least one alternative recommendation", "Missing evidence is acknowledged, not silently omitted", ] # If any criterion fails → loop back to correlator with specific feedback # If all pass AND high_severity_found → interrupt() for HITL gate 2 # If all pass AND no high severity → proceed directly to report_builder

What vs LLM: Grouping, contradiction detection, and confidence arithmetic are deterministic rule-based code. Only synthesis (producing the finding summary) and review criteria evaluation are LLM-driven. This prevents hallucinated risk scores and makes the system auditable — the confidence number is always traceable to specific evidence weights.
