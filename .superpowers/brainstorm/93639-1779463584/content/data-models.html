Section 2 — Core Data Models

TypeScript interfaces that replace the current flat state bag and raw result dicts

1 · Evidence — the atomic investigation unit

type EvidenceKind = | "vulnerability" | "maintainer_signal" | "supply_chain_signal" | "license_signal" | "reachability_signal" | "blast_radius_signal" | "release_anomaly" | "ecosystem_signal"; interface Evidence { id: string; // uuid kind: EvidenceKind; dep_name: string; skill_id: string; // which skill produced this hypothesis_id: string; // which hypothesis it relates to collected_at: string; // ISO timestamp signal: string; // human-readable finding raw_data: Record<string, unknown>; source: string; // "trivy" | "github_mcp" | "npm_registry" … source_url?: string; reliability: number; // 0–1: how trustworthy is the source confidence: number; // 0–1: how strong is this signal severity?: "critical"|"high"|"medium"|"low"|"info"; supports_hypothesis: boolean; // supports or refutes contradicts_evidence?: string[]; // ids of contradicted evidence }

2 · Hypothesis — the investigation question

interface Hypothesis { id: string; dep_name: string; // or "global" for project-wide hypotheses statement: string; // "dep X may be a supply-chain compromise vector" risk_theme: string; // "supply_chain" | "vulnerability" | "maintainer" … rationale: string; // why the planner generated this hypothesis skills: string[]; // skill ids assigned to investigate this status: "open"|"supported"|"refuted"|"inconclusive"; confidence?: number; // filled after correlation }

3 · InvestigationSkill — the cognitive protocol descriptor

interface InvestigationSkill { id: string; // "VulnerabilitySkill" | "MaintainerTrustSkill" … name: string; description: string; trigger_conditions: string[]; // when planner should select this skill required_inputs: string[]; // state fields needed: ["sbom", "repo_path"] … evidence_kinds: EvidenceKind[]; // what evidence kinds it produces execute: (ctx: SkillContext) => Promise<Evidence[]>; }

4 · InvestigationPlan — planner output (replaces Plan)

interface InvestigationPlan { concern: string; hypotheses: Hypothesis[]; skill_plan: Array<{ dep_name: string; hypothesis_id: string; skill_id: string; }>; rationale: string; // LLM explains why this plan was chosen dep_filter?: string[]; // subset of deps to focus on, or null = all }

5 · RiskFinding — the correlator output (replaces analysis_report)

interface RiskFinding { dep_name: string; risk_score: number; // 0–10 confidence: number; // 0–1: how much evidence supports this score severity: "critical"|"high"|"medium"|"low"; hypotheses: Hypothesis[]; supporting_evidence: string[]; // Evidence ids contradictions: Array<{ evidence_ids: string[]; description: string }>; missing_evidence: string[]; // what we wanted but couldn't gather summary: string; recommendation?: string; alternatives?: string[]; }

6 · New MainState — structured, not a flat bag

interface MainState { // ── Inputs ────────────────────────────────────────── repo_url: string; concern: string; job_id: string; // ── Discovery (unchanged) ──────────────────────────── project_metadata?: ProjectMetadata; sbom_cyclonedx?: CycloneDXBom; discovery_summary?: string; // ── Investigation plan ─────────────────────────────── investigation_plan?: InvestigationPlan; messages: Annotated<Message[], add_messages>; // ── Evidence (fan-in reducer) ──────────────────────── evidence: Annotated<Evidence[], concat>; // replaces subgraph_results // ── Skill execution (Send() fields) ───────────────── current_skill_id?: string; current_dep_name?: string; current_hypothesis_id?: string; // ── Correlation outputs ────────────────────────────── risk_findings?: RiskFinding[]; contradictions?: ContradictionReport[]; reviewer_feedback?: string; review_approved?: boolean; review_iterations?: number; // ── Control ────────────────────────────────────────── cancelled?: boolean; }

What this replaces: The current state has ~20 flat fields mixing discovery outputs, execution tracking, raw results, and report fragments — all in one bag. The new state has clear sections. The critical change is evidence: Evidence[] replacing subgraph_results: dict[] — now every piece of information flowing through the graph is typed, attributed, and confidence-scored.
