Architecture Approaches

Three ways to evolve the current LangGraph pipeline into a cognitive investigation platform

A

Layered Evidence Architecture

Separate the pipeline into three explicit phases: Collection → Correlation → Synthesis. Analyzers produce typed evidence objects (not raw results). A dedicated correlation layer links evidence across domains before synthesis produces risk findings.

COLLECTION (parallel) vulnerabilities ──┐ repo_health ──┤──→ evidence_store license ──┤ maintainer ──┘ CORRELATION cross_correlate ──→ signal_graph SYNTHESIS risk_scorer ──→ findings[] ──→ HITL review

Pros

  • Clean phase separation
  • Easy to add new analyzers
  • Evidence is first-class

Cons

  • Still analyzer-type-centric
  • Sequential phases = latency
  • No per-dep hypothesis framing
B

Per-Dependency Investigation Subgraphs

Each dependency gets its own LLM-driven investigation subgraph. The planner generates hypotheses per dependency and dispatches a self-contained investigation for each. Investigations run fully in parallel, each capable of running any combination of skills.

planner ──→ hypothesis(dep_A) ──→ [investigate_A] ──→ hypothesis(dep_B) ──→ [investigate_B] ──→ hypothesis(dep_C) ──→ [investigate_C] ↓ cross_dep_correlation ↓ risk_report

Pros

  • Truly hypothesis-driven
  • Max parallelism
  • Each dep fully autonomous

Cons

  • High LLM cost at scale
  • Hard to correlate across deps
  • Complex state with 100+ deps
C

Skill-Based Investigation + Shared Evidence Store RECOMMENDED

The planner generates investigation skills per dependency class — not arbitrary subgraphs. Each skill is a reusable, self-describing cognitive protocol with trigger conditions, evidence requirements, validation steps, and confidence rules. All skills write to a shared evidence store. The cross-analyzer reasons over evidence, not raw results.

planner ──→ skill_plan: { dep_A: [VulnSurface, MaintainerTrust] dep_B: [SupplyChain, BlastRadius] direct: [ReachabilityAssessment] } skill execution (parallel) ──→ evidence_store[] ↓ evidence_correlator ↓ confidence_scorer ↓ findings (high_sev?) ──→ HITL ↓ final_report

Pros

  • Skills are reusable + composable
  • Evidence is structured + queryable
  • Confidence model built-in
  • Extensible without graph changes
  • Best foundation for thesis requirements

Cons

  • More upfront design
  • Requires evidence model spec

Why C is the right call: A keeps analyzers as the investigation unit (same problem). B is too expensive and loses cross-dependency correlation. C introduces skills as the primary cognitive abstraction — the planner reasons about what to investigate and why, not which tool to invoke. Evidence becomes queryable, confidence is first-class, and skills compose without graph rewiring.
